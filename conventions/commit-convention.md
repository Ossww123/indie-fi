# 커밋 컨벤션

> 이 저장소의 커밋 메시지 규칙. **커밋할 때만 참고**한다(평소 컨텍스트에 로드하지 않음).
> 형식은 [Conventional Commits](https://www.conventionalcommits.org/)를 따르되, **제목은 한글**로 쓴다.

## ⭐ 가장 중요한 원칙

**처음 보는 사람이 이 한 줄만 읽고 무엇을 했는지 알 수 있어야 한다.**

이 저장소를 읽는 사람은 기획 문서를 갖고 있지 않다. 따라서 커밋 메시지에 **내부 용어를 쓰지 않는다.**

| ⛔ 쓰지 않는다 | ✅ 대신 이렇게 |
|---|---|
| `ADR-0007 결정 반영` | `키 발급 시 재고 초과 방지` |
| `수직 슬라이스 2 완료` | `게임 등록 화면 추가` |
| `코어 B 착수` | `키 배포 기능 추가` |
| `INV-KEYDROP-001 증명` | `동시에 몰려도 정원을 넘지 않는지 테스트 추가` |
| `foundation 슬라이스` | `회원가입 기능 추가` |

`ADR-####`, `INV-*`, `수직 슬라이스`, `코어 A/B`, `스파이크` 같은 말은 **기획 문서(`docs/`) 안에서만** 쓴다.

## 형식

```
<type>: <제목>

<본문>
```

- **헤더 한 줄만 필수.** 본문은 선택.
- 제목은 **한글**, 마침표 없음, 대략 40자 이내.
- **scope는 쓰지 않는다.** (`feat(keydrop):` ❌ → `feat:` ✅) — 내부 용어가 새어 들어오던 통로였고, 제목이 충분히 설명하면 필요 없다.
- type은 영어 그대로 둔다. 도구·관례와 맞고, 한 눈에 분류가 보인다.

## type

| type | 쓸 때 |
|---|---|
| `feat` | 사용자에게 보이는 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작은 그대로, 구조만 개선 |
| `perf` | 성능 개선 (측정 결과를 본문에) |
| `test` | 테스트만 추가/수정 |
| `docs` | 문서만 (코드 변경 없음) |
| `build` | 빌드·의존성 (.csproj, NuGet, Dockerfile) |
| `chore` | 그 외 잡일 (설정·스크립트 등) |

## 본문 (선택)

- **무엇이 아니라 왜**를 쓴다. 무엇은 diff가 말해준다.
- 성능 관련이면 **측정 숫자**를 남긴다: `p95 428ms → 72ms`.
- 여기서도 내부 용어는 쓰지 않는다. 풀어서 쓴다.

## 예시

```
feat: 회원가입 기능 추가
```

```
feat: 게임에 키 배포 일정을 등록하는 화면 추가
```

```
test: 동시에 몰릴 때 키가 중복 발급되는지 확인하는 테스트 추가
```

```
perf: 키 발급 시 재고 행을 잠그도록 변경

200명이 동시에 요청할 때 대부분이 같은 행을 두고 충돌해
성공률이 1%였다. 재고 행 단위로 잠그니 전원 성공.
p95 268ms → 72ms
```

```
fix: 오픈 시각 전에도 키를 받을 수 있던 문제 수정
```

## 규율

- **한 커밋 = 한 논리 변경.** 리팩터와 기능을 섞지 않는다.
- 한 단계(화면 1개 + 엔드포인트 1개 정도)가 끝나면 커밋한다. 커밋이 곧 진행 기록이다.
- 커밋 훅이 있으면 `--no-verify`로 건너뛰지 않는다.
- ⛔ **커밋 서명 금지.** `Co-Authored-By`, `Signed-off-by` 등 **어떤 서명·공동저자 트레일러도 넣지 않는다.** AI 협업 여부를 커밋에 표시하지 않는다.
